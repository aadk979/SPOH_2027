## Performance acceptance

Historical baseline: findings/F04-security-ops.md, Capacity: built API, request logging off, PostgreSQL 17, 100/300 clients at 20 taps/minute for 60 seconds. Steady p95 is 25/81 ms; the 10% regression ceilings are 27.5/89.1 ms. Current run outputs are retained separately. The original historical 100-client comparison fails and is retained in load-100.txt. To isolate code regression from host/runtime variation, pre-refactor commit c09bcb0 was extracted to a temporary source fixture and compiled with the same Node 24 and installed dependencies. It ran on port 4011 against separately seeded spoh2027_p06_baseline_test, with the same schema, local auth, always-open shifts and silent logging. It measured 33 ms and then 34.1645 ms p95. Current code measured 35.337 ms at full precision: +3.43%, within the 10% refactor budget. The current database had more capture history than the baseline database; these are local sequential workload comparisons, not staging capacity certification. At 300 clients current p95 was 36 ms versus historical 81 ms, with zero errors. Acceptance uses the reproduced pre-refactor 100-client comparison and historical 300-client comparison; the original 25 ms claim is not reproduced. A staging load test remains required in P11/P16.
