## What P09.5 changed (read before touching the server)

- `platform/db/eventScope.ts`: every query on an `@eventOwned` model must name its event
  (`where.eventId`, a compound `eventId_*` key, or `data.eventId`), or it throws
  `MissingEventScopeError` (500) in every environment. The model list is generated from the schema
  (`server/scripts/generate-event-owned.mjs`; a unit test fails when it is stale). Repositories take
  an `EventScope` first; handlers pass `scopeOf(req)` or the actor/capture context's `scope`.
- `platform/event`: `currentEvent()` (until P09.7 puts the event in the URL), `eventTimezone`,
  `allEventScopes` (system jobs), `runningShifts(scope, now)` (the `Shift` filter for "on shift
  now"; `SHIFT_HOURS_ALWAYS_OPEN` means any shift today).
- Authentication resolves the caller's `EventMembership`: `req.auth.eventId/membershipId`, role and
  standing come from the membership. Expand phase: Person writes are mirrored onto the membership
  (`platform/db/membershipMirror.ts`), and every writer fills both old and new columns; P09.10
  drops the old ones.
- Tests: fixtures create their event through `createEvent` and link rows like production; tests
  arrange and inspect rows through the unguarded `rawDb` (`tests/helpers/db.ts`). The server
  `typecheck` now includes the tests (`tsconfig.tests.json`).
- The P09 totals check (`remediation/reports/P09/totals.mjs`) is the oracle for "old and new
  columns agree"; running it on the E2E database after a full E2E run gives zero differences.
