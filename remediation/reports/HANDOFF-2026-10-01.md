## Things to know before touching the code

- **Event context.** The event comes from the path only. `requireAuth` resolves the membership of
  `req.requestedEvent` (set by `eventFromPath` or `eventFromAlias`); a path naming an event the
  caller is not in answers 404. Platform routes: `/auth`, `/dev-auth`, `GET /events`
  (`requirePerson`). Every other module is mounted under `/events/:eventId` **and** at its old path.
  A new route needs a case in `tests/integration/isolation.test.ts` (the first test fails
  otherwise).
- **Client.** Event screens live in `client/src/app/e/[event]/`; the slug is read after hydration
  (`shared/lib/eventPath.ts`), `EventLayout` resolves it. Feature API functions take `eventId`
  first (`shared/lib/eventApi.ts`); query keys start with it; links use `AppLink`/`useAppRouter`
  with app paths (`/home`). Client unit tests get a test event from `tests/setup.ts`.
- **Known gaps, deliberately left:** runtime settings and push-subscription sync still use the old
  (Event #1) paths from `Providers` — a person only in a second event gets compiled defaults and no
  push until P10/P12 give them a platform home. The legacy global `eventName` setting defaults to
  "Event" and is no longer displayed; P10 retires it.
- **Seed.** `prisma/seed.ts` + `prisma/fixtures/devEvent.ts`: SPOH 2027-shaped event (days are
  offsets from today) plus a second event "Dry Run" with `multi@spoh2027.test` on both rosters.
  Production: administrator only. The E2E database is recreated (drop, `migrate deploy`, seed) —
  it must be re-seeded on each new day, since its "today" is a seeded day.
- **Visual database** was seeded on 28 Sep with the old seed and is not rebuilt; its baselines were
  updated only where labels changed. See `client/tests/visual/README.md`.
