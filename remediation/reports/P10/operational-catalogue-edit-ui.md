# Reviewed generated catalogue editing — partial P10.8

The generated catalogue adds reviewed set/remove controls for the existing
14 event and three station operational keys. Field types, bounds, numeric choices
and enum options come from the generated registry metadata. Unsupported metadata
offers no set control. Boolean, integer/fractional number, bounded text, discrete
numeric choice and enum-selection controls replace arbitrary JSON entry.

A review shows the current scoped value, selected/source versions and inheritance,
the generated description, visible input limits and the validated proposed value.
Blank or nonfinite numeric input stays invalid rather than becoming zero. Empty
enum selection remains a valid proposal. The shared request schema validates and
normalises the actual body; the preview shows that same registered value.

Every fresh request requires a bounded reason and deliberate confirmation. Any
proposal or reason edit clears confirmation. Set creates a selected-scope override;
remove uses current inheritance and refuses a zero-version scope. Archived events
offer no fresh writes. Existing privacy, counts, attendance security and platform
paths remain excluded by the public operational selection.

The existing guarded API owns writes, reviewed-version checks, transaction/lock
ordering, history, audit and identifier-only retry receipts. This slice changes
no server writer, database schema or scheduler. The extracted review hooks now
accept typed editable values and error-field mapping. Refreshing a stale review
preserves its explicit proposal while clearing reason, confirmation and prior
intent. Capture and historical-restore wrappers keep their reason-only behaviour.

Pending/ambiguous requests freeze one body/UUID and lock fields, scope, collapse
and review navigation. Nonpermission read failure retains an ambiguous review
and permits the identical retry; it blocks fresh requests. Source/value/version
changes require a new review. Current denial clears private owner values and stays
sticky above query observers. A new event/person remounts a collapsed owner.

## Generated normalization defect

The new text validation check exposes a generator mismatch: the authored registry
trims before checking length, but generated contracts previously check length
before trimming. That accepts whitespace which becomes empty and rejects padded
text whose trimmed length is valid. The generator now preprocesses strings before
the same generated bounded schema; nonstring types remain rejected. Its generated
output is regenerated by the tool, with no hand-edited metadata/defaults/bounds.

Two shared contract checks fail before this fix. The accepted checks cover both
public text keys; direct generated-schema checks also cover the existing eventName
key. An authored/generated registry parity check covers null, wrong types, blank,
whitespace, valid text, exact trimmed maximum and overlong text for all three
normalised keys. This aligns contract validation with the existing registry rather
than introducing a new setting producer or consumer migration.
